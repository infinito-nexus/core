The CLI test then reads `no such service: agent-hermes-<id>` and every relayed prompt answers 502; `web-app-baserow`'s Playwright spec sees the same cause as HTTP 400. Compose is unaffected: its `network_driver` is `bridge`, local scope, and attaching a container works. `SwarmBackend.create()` already attaches the agent correctly through `TaskTemplate.Networks`, so only the broker's own attachment is impossible. Fixing it is a decision about the isolation boundary, not a code detail, and the operator has deferred it: listing the broker's own overlay in the agent's `Networks` at create time removes the hot-attach and keeps the diff small, but gives up network isolation between two owners' agents and leaves `API_SERVER_KEY` plus the per-agent volume as the only tenant separation; keeping the per-agent overlay instead means reaching the agent over a published port, which is cluster-wide reachable. Until it is decided, the swarm path is known broken and its jobs stay red.
