# Todo

- Bookmarks and sessions are not persisted: the role mounts no volume for `/app/.data` (upstream `src/util.js` keeps the SQLite files there, the role has no `meta/volumes.yml`), so every container recreate wipes all bookmarks and signs the owner out, while the README says the role persists its SQLite data. Options: declare a volume mounted at `/app/.data`, or correct the README.
- `PUBLIC_BASE_URL` is not rendered into `templates/env.j2`, so the app falls back to `localhost`: every page links its feed and OpenSearch description as `https://localhost/index.xml` and `https://localhost/opensearch.xml` (measured on `/about`), and the bookmarklet on `/admin` is built from the same domain (upstream `src/routes/admin.js`). Option: render `PUBLIC_BASE_URL` from the role's canonical domain.
- The CSP blocks the inline `onsubmit` confirm of "Clear bookmarks" on `/admin/data` (upstream `src/pages/admin/data.hbs`; measured console error "Executing inline event handler violates ... script-src-attr 'self'"), so one click deletes every bookmark without a confirmation. Options: allow that handler's hash in `meta/csp.yml`, or replace the handler in the image build.
- `meta/services.yml` builds `ref: main`, an unpinned branch (head `3437b8e` on 2026-10-10), so any rebuild can change the markup the design stylesheet and spec select on. Option: pin the commit.
- The site name has no setting of its own upstream: `server.js` sets `site_name` once at start from `actorInfo.displayName || 'Postmarks'`, and `actorInfo` comes only from `/app/account.json`, whose presence switches Postmarks into fediverse mode (`src/util.js`), so `templates/design.js` rewrites the page title and the header name in the browser while the server-rendered HTML and both Atom feed titles keep `Postmarks`. Option: an upstream `SITE_NAME` setting that does not require `account.json`, e.g. `process.env.SITE_NAME || actorInfo.displayName || 'Postmarks'` in `server.js`, rendered from the design title.
- The owner key `ADMIN_KEY` is a role-generated secret (`secrets.credentials.admin_key`) independent of the administrator account, so with `sso` off a rotated administrator password never reaches Postmarks and the native sign-in needs a second credential. Option: render `ADMIN_KEY` from `lookup('users', 'administrator').password` so it converges on every deploy.
