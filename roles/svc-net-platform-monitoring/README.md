# Platform Monitoring Share

## Description

The instance side of the platform monitoring share: a customer instance shares exactly the kinds its host value `platform_monitoring` switches on with the platform's [Checkmk](https://checkmk.com/) and Prometheus, and the instance enforces that share itself.

## Overview

`platform_monitoring` is a host value with the booleans `reachability`, `agent`, `health`, `system` and `traffic`; any other key is refused, and an absent value or key means `true` (Decision 3). [utils/platform_monitoring.py](../../utils/platform_monitoring.py) holds the schema, the Semaphore inventory guard refuses a broken value before a task runs, and the filters of [plugins/filter/platform/monitoring.py](../../plugins/filter/platform/monitoring.py) resolve it during the deploy.

The platform injects its Checkmk server, site and address and the SHA-256 of the agent script its site serves into the workspace deploy's environment (`PLATFORM_CHECKMK_SERVER`, `PLATFORM_CHECKMK_SITE`, `PLATFORM_CHECKMK_ADDRESS`, `PLATFORM_CHECKMK_AGENT_SHA256`): `workspace apply` of `web-app-semaphore` derives them from its own `web-app-checkmk` and reads the digest from the site itself. It injects the internet address of its own `web-app-prometheus` host the same way (`PLATFORM_PROMETHEUS_ADDRESS`); in a workspace deploy `/federate` answers that address only, loopback included in the refusal, so a leaked bearer is useless from anywhere else. An agent share while one is empty or malformed fails the deploy, as does a federated share without a valid Prometheus address; a loopback or unspecified address, which the `127.0.0.1` default of a platform host's unset `networks.internet.ip4` gives, fails both by name (`platform_address`), and the Semaphore inventory guard refuses any `applications.svc-net-platform-monitoring` or `applications.web-app-checkmk` value; only `platform_monitoring` and `ssh_host_key` stay inventory values. A workspace deploy (the task environment names `WORKSPACE`) never reads these credentials from the inventory: it derives their OpenBao references from `WORKSPACE` and the host (`AGENT_KEY_REFERENCE`, `DIGEST_REFERENCE` of [utils/platform_monitoring.py](../../utils/platform_monitoring.py)), the paths the platform's `monitoring` template writes (Decision 1). The metricz bearer of `web-app-prometheus` is the instance's own and stays an inventory credential. The bearer itself stays with the platform: the instance holds its digest only. A deploy outside a workspace task uses the generated `credentials.federation_token_sha256` of its own inventory.

The instance's `/metricz` admits only the bearer `credentials.metricz_bearer` of [web-app-prometheus](../web-app-prometheus/meta/secrets.yml), which its own `nginx-metricz` job presents, so the traffic series leave the instance only through `/federate`.

The core `release` template, on a platform that runs monitoring, removes the agent script our install marked while it still matches the recorded digest, the key line and, on the stack host, every digest file with all its lines, proves them gone on disk over SSH (no HTTP round trip, so a stopped instance releases too) and only then erases the host's federation token, digest record and agent key mirror in OpenBao. The Checkmk host and the scrape target stay the store's job, which dispatches `monitoring remove` on discharge.

## Features

- **`agent`:** Checkmk pulls the agent over SSH (Decision 6). True installs the agent script `check_mk_agent` of the platform's site from its agent directory over verified TLS, refused unless its SHA-256 equals the digest the platform injects, a plain script that opens no listener, so no port 6556 and no agent controller exist at any point of the install. It then adds the platform monitoring public key, read from `AGENT_KEY_REFERENCE` of [utils/platform_monitoring.py](../../utils/platform_monitoring.py) for the task's `WORKSPACE`, to the login user's `authorized_keys` as one line locked to a forced command, `restrict` and `from=` the Checkmk address (`agent_key_line`); the forced command prints the section `<<<infinito_workspace>>>` with `ws-<WORKSPACE>` before it execs `check_mk_agent`, so the platform drops the agent output of a host deployed for another workspace than the Checkmk host it pulls for. The install refuses a host whose `/usr/bin/check_mk_agent` exists without the marker `/etc/infinito.nexus/platform-monitoring-agent`, so it never replaces or marks an agent the host installed otherwise; it writes the marker, which records the SHA-256 of the script it installed, only after its own download landed, and a failed first download removes the script and marker it left. Install, removal and release touch the script only while its SHA-256 equals the recorded one; a script another install changed is foreign: it stays, the marker goes and the run says so. False removes exactly that line, the script only while it is ours, then the marker. A deploy outside a workspace task (no `WORKSPACE`, such as the role's own CI deploy) has no platform to share with and runs that removal too. The private key stays with `web-app-checkmk`.
- **`health`, `system`, `traffic`:** the federation endpoint `/federate` of the instance's Prometheus vhost, rendered by [federate.conf.j2](../web-app-prometheus/templates/nginx/federate.conf.j2) on hosts in this role's group, answers only the series of the kinds switched on, drops whatever query the caller sends, and admits only a bearer whose SHA-256 digest a line of the digest file holds: one line `<host_segment> <digest>` per host, which each deploy writes or drops for its own host on the stack host with [digest_line.py](./files/python/digest_line.py) under the `flock` on `<file>.lock` that the release takes too. With all three off the vhost answers 404 and the deploy drops the host's line. In a workspace a worker of a swarm stack fails the deploy for any of the three: it cannot reach its stack host, whose `/federate` serves the stack, so the kinds belong on the stack host. A Prometheus vhost outside this role's group keeps its plain `/federate` behind the vhost's own gate.
- **`reachability`:** checked from outside by the platform; nothing runs on the instance.
