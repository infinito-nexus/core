# Todos

- The image pin `v4.6.2` in `meta/services.yml` (`mastodon` and `streaming`) is stale: upstream released `v4.6.9` on the 4.6 line and `v4.7.3` (2026-10-01). A bump to 4.7 may rename the semantic `--color-*` tokens that `templates/custom.css.j2` maps; the design spec catches that. Options: bump to `v4.6.9` now, or to `v4.7.3` together with a check of the token names in `app/javascript/styles/mastodon/theme/`.
- With `sso` off nothing provisions a password Mastodon's own `/auth/sign_in` accepts: `tasks/05_administrator.yml` creates the administrator with `tootctl accounts create`, which generates a password nobody keeps, so the administrator persona stays blocked and the native sign-in of `files/playwright/test-design.js` (e-mail `ADMIN_EMAIL`, password `ADMIN_PASSWORD`) fails in the sso-off variants. The form also takes the e-mail, not the username the shared persona flow types. Options: converge the administrator password in a task after the create (a `rails runner` script that checks `valid_password?` and updates on a mismatch, the value passed as `-e NAME` plus `environment:`), and set `ADMIN_NATIVE_USERNAME` to the administrator's e-mail so the shared flow fills the right field.
- `tootctl accounts create` prints the generated password (`New password: …`) to stdout, which the create task in `tasks/05_administrator.yml` registers; its `no_log` follows `MASK_CREDENTIALS_IN_LOGS`, which local deploys disable, so a run with `-v` prints the administrator's working password. Option: drop the `New password:` line in the pipe before Ansible registers the output.
- `tasks/05_administrator.yml` "Unblock the administrator username" reports changed on every deploy (measured 2026-10-11 in the baseline deploy and four consecutive role syncs; the baseline printed "Unblocked 1 username block(s) for administrator"), so a username block for the administrator is recreated between runs. Options: find what recreates the block and stop it, or make the unblock idempotent by not recreating it.
