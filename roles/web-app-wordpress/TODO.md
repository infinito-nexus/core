# To-dos

- Core version drift: the image `wordpress:7.1.2` ships core 7.1.2 (`/usr/src/wordpress/wp-includes/version.php`), the data volume of a fresh install ran 7.1.3 when it was first measured, 77 minutes after its creation (`wp core version`, body class `version-7-1-3` in wp-admin). WordPress applies minor core updates in the background inside the volume, so the running version leaves the pin in `meta/services.yml`. Options: set `WP_AUTO_UPDATE_CORE` to `false` in `wp-config.php` and update through the image, or keep the background updates and stop treating the pin as the running version.
- `tasks/02_install.yml` passes the administrator password to `wp core install` as `--admin_password=<value>` on the command line of `container exec`, where the process list of the host shows it for the run of the command. Options: `wp core install --prompt=admin_password` with the value on stdin, or `wp user update <login> --prompt=user_pass` after an install that sets a throwaway value.
- A `site-owner` member who is no inventory user gets a site at the first SSO login but, without a wildcard certificate, no vhost, so that site is reachable only where a wildcard certificate is available. Options: add Keycloak members to `domains.served` at deploy from the directory (`tasks/utils/rbac/members.yml`), or leave such members to the wildcard modes.
- No variant enables `litellm` together with Multisite, so `files/playwright/addons/infinito-ai-engine-network.spec.js` skips in every round and the AI Engine network guard is proven by `tests/unit/python/roles/web-app-wordpress/test_ai_engine_network_guard.py` only. Options: enable `litellm` in the Multisite variant, or add a Multisite variant with `litellm`.
- On the clearnet pass the REST nonce request of biber's own site answered 400 (`/tmp/compose-deploy-iam-19.log`, around line 72429). The check now lives in the test "biber: the own site keeps its SSO settings out of reach and routes its sign-in to the main site (multisite)" of `files/playwright/test-multisite-rbac.js`, which checks own sites on the canonical network in every pass, so the Tor pass reaches the same request. `admin-ajax.php` answers 400 to `rest-nonce` when it sees no session, and the request follows redirects, so the 400 may also end a redirect chain; the assertion names the final URL and the start of the body. Open: find the cause in the next run that reaches the request.

Open: rerun both specs on an onion and a clearnet pass; decide whether application passwords stay https-only on onion hosts; and let `files/mu-plugins/infinito-oidc-rbac-mapper.php` drop an over-long website claim instead of failing the whole profile sync of that user.
