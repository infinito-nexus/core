# 074 - Header-trust backends reachable only through openresty

## User Story

As an operator, I want every application that logs a user in from a proxy-set identity header to be reachable only through openresty, and openresty to clear or overwrite that header on every location, so that no client can impersonate a user, for example with `X-Forwarded-Preferred-Username: administrator`.

Implements [infinito-nexus/core#1089](https://github.com/infinito-nexus/core/issues/1089).

### Backend ports

- [ ] In swarm, no backend port of a header-trust role answers on any node address from outside the swarm. A probe from a host that is not a swarm node gets no TCP connect on `ports.local.<proto>` of each inventoried role.
- [x] In swarm, `container_ports` publishes no `ports.local` port carrying a host ip. The decision runs on the effective mode (`compose_mode_force` or `DEPLOYMENT_MODE`). Edge proxy, mail, TURN and SSH ports stay published. (`plugins/lookup/container_ports.py`; `tests/unit/python/plugins/lookup/test_container_ports.py`, where `test_swarm_keeps_public_term_with_ip` pins that a `ports.public` term keeps its ip and fails when the drop ignores `ports.local`.) Exception: a TCP `ports.local` port the node onion forwards (`exposed: true` or `ports.onion`) of an application `svc-net-tor` is deployed for is published in `mode: host` only when it is in `SWARM_ONION_HOST_BACKENDS`, the one list the stack host evaluates right after placement, from the parked applications carrier, in every play that places the shared services. Its service is pinned to the stack host's node name, and the `prerouting` chain of the swarm node baseline drops every packet to it that does not arrive on `lo`, before Docker's DNAT. That drop covers the list and every non-public TCP port a live service still publishes in host mode, so a port leaves it only once the post-deploy refresh reads nothing publishing it. A custom role that publishes a non-public port in host mode for its peers is dropped as well, which matches the `local` contract in [layout.md](../contributing/design/role/services/layout.md): such a port is bound on `127.0.0.1` and reachable only from the host. The read behind the drop fails when the stack host is an active swarm member without control, instead of returning nothing. Both the deploy and the role sync load the drop before their first stack deploy: the deploy through the svc-swarm-node join or, when it skips svc-swarm-node, through the ingress guard refresh, the sync through that refresh. (`host_published` in `plugins/lookup/tor_ports.py`, `tasks/utils/constructor/onion_backends.yml`, `tasks/stages/01_constructor.yml`, `roles/svc-swarm-node/tasks/utils/ingress_guard/read.yml`, `playbook-sync.yml`, `SWARM_ONION_HOST_BACKENDS` and `SWARM_ONION_GUARDED` in `group_vars/all/18_swarm.yml`, `swarm_onion_guarded` in `plugins/filter/swarm_ingress_guard.py`, `roles/svc-swarm-node/templates/nftables.conf.j2`, `roles/sys-svc-container/templates/deploy.yml.j2`; `tests/unit/python/plugins/lookup/test_container_ports.py`, `tests/unit/python/roles/svc-swarm-node/test_onion_backend_guard.py`, `tests/unit/python/roles/svc-swarm-node/test_onion_backend_drop_lifecycle.py`, `tests/unit/python/roles/svc-swarm-node/test_ingress_guard_read.py`, `tests/unit/python/roles/sys-svc-container/test_onion_stack_host_pin.py`.)
