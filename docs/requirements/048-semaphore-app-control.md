# 048 - Semaphore App Control and Foreign-Server Deploy

## User Story

As a platform operator, I want members of the `operator` role group to pause and resume every deployed Infinito.Nexus application from Semaphore, and members of the `administrator` role group to deploy Infinito.Nexus from Semaphore to a foreign server, so that routine control and remote rollouts run through one audited, role-gated web UI instead of a shell on the host.

## Decisions (operator-confirmed 2026-10-29; do not re-litigate)

1. **Contract in `meta/services.yml`.** Every invokable role declares a `semaphore` entry with `enabled`, `shared`, the control flag `control` and `status`. `enabled` and `shared` follow `'web-app-semaphore' in group_names`; `control: true` puts the application under Semaphore control; `status` is `started` or `stopped` and is the state the deploy creates the application in.
2. **Control plane is exempt.** `web-app-semaphore`, `web-app-keycloak`, `svc-db-postgres`, `svc-db-openldap`, `svc-prx-openresty` and `web-app-gitea` (it holds the inventory repository) declare `enabled: false`, `control: false` and `status: started`, each with a `# nocheck:` reason, so no Semaphore run can cut off its own way back.
3. **Templates per application plus all.** Semaphore offers `stop <application>` and `start <application>` for every deployed application with `control: true`, plus `stop all` and `start all` over exactly that set.
4. **RBAC.** A new `operator` role in `roles/web-app-semaphore/meta/rbac.yml` maps to the Semaphore project role `task_runner` and may run the stop and start templates. Only `administrator` may run the foreign-server deploy. Every other account sees neither.
5. **Runner.** Templates execute in a dedicated Semaphore runner container built on the Infinito.Nexus image, pinned to the image tag of the current deploy: CI passes its image tag through and never builds `latest`; production uses the release version. The runner holds no Docker socket, does not run as root, and reaches every host only over SSH with a key from the Semaphore key store. Each platform project has a runner of its own, and workspace projects run on runners of their own; see [102](102-one-semaphore-runner-per-workspace.md).
6. **Paused state.** Pausing leaves no running instance of the application: in compose its containers and `*.infinito.nexus` timers stop, in swarm every service of its stack runs 0 replicas. Resuming restores the declared state.
7. **Paused page.** While an application is paused, nginx answers every one of its vhosts with HTTP 503 and a page that shows an animation of a beaver sleeping behind a pause sign, states that the service is paused, and lists the platform operator's contact channels from `service_provider.contact` (email, Mastodon and the others declared there). The page text is multilingual and managed through the `core` `.po` catalogs.
8. **Shared foreign target.** The development stack's `compose.yml` gains a `target` service (systemd, sshd, wildcard resolver) that starts by default with `make compose-up` and in CI and serves compose and swarm rounds alike. One shared script resets it before each use. The `web-app-docs` instruction replay moves onto this target; its own `machine.sh`, `sshd.sh`, resolver and compose project are refactored into the shared logic.
9. **Foreign deploy source.** The deploy template deploys from an inventory repository bound as a Semaphore repository. Private repositories are supported and are the default; the repository URL and its deploy key are mandatory inventory values with no default. The Semaphore test variant includes `web-app-gitea`, which hosts a private inventory repository for the `target` service.

## Acceptance Criteria

- [x] Every invokable role's `meta/services.yml` declares `semaphore` with `enabled`, `shared`, `control` and `status`, where `enabled` and `shared` are `"{{ 'web-app-semaphore' in group_names }}"`, `control` is a literal boolean and `status` is `started` or `stopped`. `test_every_invokable_role_declares_the_contract` in [test_semaphore_contract.py](../../tests/lint/ansible/roles/meta/test_semaphore_contract.py) (line 278) passes over every invokable role. Only the six control-plane entries of the next criterion carry an entry-level `semaphore-contract` reason; no other role suppresses `enabled`, `shared` or `status`, and every other suppressed field is a literal `control: false` with its reason. The removed-entry, quoted-control, static-flag and missing-key cases of [the lint's unit test](../../tests/unit/python/tests/lint/ansible/roles/meta/test_semaphore_contract.py) are its negative controls.
- [x] `web-app-keycloak`, `svc-db-postgres`, `svc-db-openldap`, `svc-prx-openresty` and `web-app-gitea` declare `semaphore` with `enabled: false`, `control: false` and `status: started`, each carrying a `# nocheck:` reason. In `web-app-semaphore` the `semaphore` entry is the Semaphore container itself: `enabled` stays the container flag, and the entry adds `shared`, `control: false` and `status: started`, carrying a `# nocheck:` reason.
- [x] A lint fails for an invokable role whose `meta/services.yml` lacks the `semaphore` entry, whose `control` is not a literal boolean, or whose `status` is neither `started` nor `stopped`, unless the entry carries a `# nocheck:` reason, and it is observed failing on a role with the entry removed and on a role with `status: paused`.
- [ ] A deploy that creates an application with `status: stopped` leaves it paused (no running instance, the paused page on its vhosts), and one with `status: started` leaves it running.
- [ ] A redeploy of an application keeps the state Semaphore last set for it; `status` decides only the state the application is created in.
- [x] `roles/web-app-semaphore/meta/rbac.yml` declares an `operator` role, and the RBAC reconcile grants its members the project role `task_runner` in the provisioned project. [meta/rbac.yml](../../roles/web-app-semaphore/meta/rbac.yml) declares it (line 3), `SEMAPHORE_RBAC_LOGIN_ROLES` hands its members to the hook, and [reconcile.sql](../../roles/web-app-semaphore/files/sql/rbac/reconcile.sql) grants `task_runner` in the project named by `SEMAPHORE_RBAC_PROJECT` (lines 117-148), promotes a `guest` row (lines 151-178) and revokes the grant of every non-member (lines 181-207). `test_the_operator_role_is_declared_read_and_granted` and `test_grants_touch_only_task_runner_rows_of_the_provisioned_project` in [test_reconcile_sql.py](../../tests/unit/python/roles/web-app-semaphore/files/test_reconcile_sql.py) hold that shape, with an undeclared `operator` role as the negative control.
- [ ] A deploy provisions, idempotently, a Semaphore project `Infinito.Nexus` holding `stop <application>` and `start <application>` for every deployed application with `control: true`, plus `stop all` and `start all`; a second deploy changes nothing.
- [x] A dedicated Semaphore runner container runs every template; its image is the Infinito.Nexus image with the tag of the current deploy, never `latest`; it mounts no Docker socket, runs as a non-root user, and reaches hosts only over SSH with a key held in the Semaphore key store. The server sets `SEMAPHORE_USE_REMOTE_RUNNER=true` unconditionally ([env.j2](../../roles/web-app-semaphore/templates/env.j2) line 17), the `task-runner` service mounts only its runner-token secret ([meta/volumes.yml](../../roles/web-app-semaphore/meta/volumes.yml) lines 8-16) and runs as UID and GID 64101 through the last `USER` of its [Dockerfile](../../roles/web-app-semaphore/files/runner/Dockerfile) (line 36), and its env carries no key, so the app-control and deploy keys reach it only from the key store of the project (`ensure_ssh_key` in [project.py](../../roles/web-app-semaphore/files/python/project.py) line 153). - [ ] In compose, `stop <application>` leaves no running container of that application and its `*.infinito.nexus` timers stopped; `start <application>` brings both back.
