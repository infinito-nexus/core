# 094 - Nextcloud user_oidc Provider Registration

## User Story

As a platform operator who runs Nextcloud with the `user_oidc` plugin, I want the deployment to register the Keycloak provider in `user_oidc` with Nextcloud's own Keycloak client, so that Nextcloud signs its users in to their existing accounts and ends their sessions when Keycloak sends a back-channel logout token.

## Background

[066 - Logout everywhere per network and device](066-server-side-logout-everywhere.md) keeps Nextcloud on the shared client: `oidc_login` (the default with LDAP) and `sociallogin` (the default without LDAP) receive no logout token, and `user_oidc` does, but `lookup('sso_oidc_plugin')` (`plugins/lookup/sso_oidc_plugin.py`) can select `user_oidc` only through `services.sso.oidc.plugin`, and the role does not register its provider yet (`roles/web-svc-logout/README.md`, row `web-app-nextcloud`). The operator decided on 2026-11-03 that the provider registration is a requirement of its own.

`user_oidc` v8.12.0 documents the provider command `occ user_oidc:provider`, the back-channel logout URL `/index.php/apps/user_oidc/backchannel-logout/<provider identifier>` with "Backchannel Logout Session Required", and a user id that hashes the provider id with the user id unless the provider option turns that off ([README](https://github.com/nextcloud/user_oidc/blob/v8.12.0/README.md)).

## Acceptance Criteria

- [x] With `lookup('sso_oidc_plugin')` resolving to `user_oidc`, the deploy registers exactly one Keycloak provider through `occ user_oidc:provider` with the realm's discovery URI and the id and secret of Nextcloud's own client, and a second deploy converges it without creating another provider: `roles/web-app-nextcloud/tasks/addons/user_oidc.yml` looks the identifier `NEXTCLOUD_USER_OIDC_PROVIDER` up exactly, then runs the command on every deploy, and upstream `lib/Command/UpsertProvider.php` (v8.12.0) updates the provider of an existing identifier instead of adding one. The client secret reaches the command through `--clientsecret-env` from stdin, never on argv; `test_the_provider_is_registered_with_the_own_client`, `test_the_client_secret_travels_on_stdin_and_never_on_argv` with its negative control, and `test_the_registration_is_one_idempotent_upsert` in `tests/unit/python/roles/web-app-nextcloud/test_user_oidc_provider.py`.
- [x] `web-app-nextcloud` declares its own client under `services.sso.oidc.clients` in `meta/services.yml` and renders it in `templates/keycloak/clients.json.j2`, and `roles/web-app-keycloak/filter_plugins/oidc_clients.py` includes it without a change on the Keycloak side: the declaration renders to `{user_oidc: nextcloud-user-oidc}` only while the plugin resolves to `user_oidc` and to `{}` otherwise, so `kc_declared_client_apps` lists Nextcloud only then; `test_user_oidc_brings_the_own_nextcloud_client` and `test_nextcloud_stays_on_the_shared_client` in [test_backchannel_clients.py](../../tests/unit/python/roles/web-app-keycloak/templates/test_backchannel_clients.py), `test_another_plugin_declares_no_client_to_register_with` in `tests/unit/python/roles/web-app-nextcloud/test_user_oidc_provider.py`.
- [x] That client has `frontchannelLogout: false`, `backchannel.logout.session.required: "true"`, the `backchannel.logout.url` `/index.php/apps/user_oidc/backchannel-logout/<provider identifier>` on Nextcloud's canonical origin, and redirect URIs, web origins and post-logout redirect URIs for every network sibling through `lookup('network_urls', ...)`: `backchannel_findings` and the URL assertion in `test_user_oidc_brings_the_own_nextcloud_client`, plus `test_every_backchannel_client_is_safe_and_reaches_every_network`, which now covers it. - [ ] The provider maps the Nextcloud user id to the `nextcloud_uid` claim, else to `preferred_username`, and turns the hashed unique user id off, so an existing account signs in to the same account after the switch and no second account appears. Nextcloud's own Keycloak client maps the user attribute `nextcloud_uid`, which only admins see and set, into that claim (`test_the_own_client_hands_user_oidc_the_mapped_user_id`, `test_only_admins_see_and_set_the_nextcloud_user_id`). With LDAP, upstream `soft_auto_provision` (on by default) signs the claim into the existing `user_ldap` account of that user id instead of creating one. - [x] The provider maps display name, email, quota and groups from the claims, and the group claim provisions the RBAC groups the other plugins provision: `--mapping-display-name`, `--mapping-email`, `--mapping-quota`, `--mapping-groups` and `--group-provisioning=1` (`test_profile_quota_and_groups_come_from_the_claims`). Proven by `TestNextcloudAdminClientRole` and `test_the_default_plugins_render_the_realm_byte_identically` in [test_backchannel_clients.py](../../tests/unit/python/roles/web-app-keycloak/templates/test_backchannel_clients.py), `TestDeclaredClientRoleGrants` in `tests/unit/python/roles/web-app-keycloak/filter_plugins/test_oidc_clients.py`, and `test_the_admin_client_role_provisions_nextcloud_s_admin_group` with its negative control in `tests/unit/python/roles/web-app-nextcloud/test_user_oidc_provider.py`.
