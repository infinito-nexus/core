# Runner Pool 🏃

Commands that size and report the local runner pool: `count` prints the default number of pool runners and the RAM, CPU and disk terms it is the minimum of, and `cleanup` (behind `make runner-cleanup-report`) prints every held job with its age and every svc-runner job stack the infra runner's Docker lists that no running or held job owns, removing nothing. While the pool is off (`INFINITO_DEPLOY_VIA_POOL` unset or `false`), `cleanup` says so and exits `0` without a row. Like `make runner-status` and `make runner-release`, `cleanup` asks nothing of the infra runner while the job queue is missing, while this user cannot write it (it names the `runner-queue` group to join), or while its layout lets a job swap a folder under its users: a root without the sticky bit, or a `jobs/`, `logs/` or `runners/` that is missing, a link or owned by another user than the root. It then names `make infra-update` with `INFINITO_DEPLOY_VIA_POOL=true`, which restores the layout, and exits `2`.
