# Runner Pool 🏃

Building blocks of the local runner pool, which runs every local deploy as a job of one of N runners. Nothing here calls Docker or touches a cache itself; the loop runs the job and teardown commands its caller hands it.

## Modules 🧭

| Module | Purpose |
|---|---|
| [count.py](count.py) | The default pool size behind `make runner-count`: the minimum of RAM, CPU and disk divided by the per-deploy budgets, at least 1. The disk term subtracts the remaining cache growth, the sum of `max(0, cap - used)` over the rows `make cache-status` prints, and `INFINITO_CACHE_DISK_FLOOR` from the free disk. `INFINITO_RUNNER_COUNT` overrides the result. |
| [jobs.py](jobs.py) | The file-based job queue below the cache base (`<DIR_CACHE>/jobs`, beside the slot registry, outside the four cache paths): submit, claim by one idle runner under a lock, the states `queued`, `running`, `held`, `done` and `failed`, hold and release, the queue position, the wait with an optional timeout that withdraws the job, the log follow that returns the job's exit status, the per-runner rows of `make runner-status`, and the cleanup report of held jobs and job stacks without a record. A runner process holds its registration under `runners/` locked while it serves, so the lock tells a live runner from one that is gone, whatever killed it. Job ids, runner and stack names are checked before they name a path or a project; a record that is no well-formed job (a stray file, a name that is not its id, a missing, unknown or mistyped field) is left out and named once on stderr, and one withdrawn while it is read is gone. It opens every file without following a link and without blocking, uses only regular files, and creates new ones exclusively, since every job can write the queue. It creates the root `3770`, sticky so only their owner renames or removes `jobs/`, `logs/` and `runners/`, those three `2770` and every file `0660`, so the `runner-queue` group of `svc-runner` shares the queue between the operator and the runners and nobody else reads it; it never renames or removes an entry of the root. It, `loop.py` and their imports run inside the runner image, whose `python3` has no third-party library. |
| [loop.py](loop.py) | The loop every `local` runner of `svc-runner` runs: register and hold its registration while it serves, end every job it still ran when it last stopped (exit 137, never run again), claim the oldest queued job, whose checkout must be an absolute path resolving below one of the runner's worktree roots, never a root itself, and holding the job entry (126 otherwise), remove the copy of the job before as root through a throwaway container of `INFINITO_RUNNER_IMAGE` that mounts `INFINITO_RUNNER_INSTALL_DIR` alone, copy what git sees in that checkout (tracked files and untracked ones no ignore rule covers, never `.env`) into the runner's own `INFINITO_RUNNER_CHECKOUT` below it, listing the copied files in `checkout.files` there so a later sync removes what git no longer lists and nothing the job wrote, add the checkout's `custom.env`, mode `0600`, with `INFINITO_POOL_RUNNER=true` and `INFINITO_DEPLOY_VIA_POOL=false` pinned and a `.git` file naming the checkout's mounted git directory, and run `<copy>/scripts/tests/deploy/job/entry.sh make <target> <args>` there, so the job writes into a tree of its own and a held stack keeps running from it while the worktrees stay read-only mounts; the job gets the runner's environment minus its own loop's keys (`PYTHONPATH`, `RUNNER_SRC_DIR`, the queue, the roots, the install directory and the copy), `PYTHONDONTWRITEBYTECODE=1`, the two pinned keys and `INFINITO_STACK_NAME` set to the runner's job stack, so it uses the infra runner's caches but neither starts nor joins it, and its output goes to the job's log; remove that stack unless the job holds it, and finish the job with the deploy's exit status. A link at the copy is removed, never followed, and nothing outside the install directory is removed. A job whose entry never ran (126, or 127 when the copy fails or the entry cannot start) left no stack and fails whatever its hold. When the removal as root fails, the runner is marked `failed` with that path and the error in its registration, retries the removal every `FAILED_POLL` seconds instead of every poll, and claims nothing until a later removal succeeds. A held runner, and one whose stack removal failed, claims nothing until `make runner-release job=<id>` removes the stack. |
| [role.py](role.py) | What the host-side pool commands read from `svc-runner` through the YAML cache, kept out of the runner's imports: the `runner-queue` group and gid the refusal of an unwritable queue names, the refusal of a queue whose root lacks the sticky bit or whose `jobs/`, `logs/` or `runners/` is missing, a link or owned by another user than the root, the compose project prefix of the job stacks with the one `<prefix>-<N>` pattern `make runner-release` and `make runner-cleanup-report` both match, the one check of a job an operator names with `job=<id>` (held or running, its record naming its runner's own job stack), and the `DOCKER_HOST` of the socket `svc-runner` opens in the queue for the infra runner's daemon. |
| [checkmk_local_check.py](checkmk_local_check.py) | The Checkmk local check lines: one service per runner, held job, cache and the disk floor. A held job warns from `INFINITO_HELD_JOB_WARN_AGE` (default `24h`) and is critical from `INFINITO_HELD_JOB_CRIT_AGE` (default `7d`); a cache above its cap and free disk below the floor are critical. |

## Calibration 📐

The per-deploy budgets come from `inventories/development/runner-calibration.yml`, which records the measured full deploy they come from:

```yaml
applications: [web-app-dashboard, web-app-keycloak]
commit: dde9318aac
date: 2026-11-07
peak_memory: 8g
cpus: 4
disk_growth: 20g
```

The values above only show the shape. Until a measured deploy is recorded, `make runner-count` refuses unless `INFINITO_RUNNER_COUNT` sets the count, and [test_runner_calibration.py](../../tests/lint/repository/test_runner_calibration.py) fails on a budget without its record.
